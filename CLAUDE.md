# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A personal Mandarin study site with three parts:
- **Web pages** (`page/`, `index.html`) — static HTML/JS/CSS apps, no build step
- **Python scripts** (`scripts/`) — data pipeline for creating and printing flashcard CSVs
- **Data** (`data/`) — flashcard CSVs and lookup maps consumed by both pages and scripts

The site is deployed from the `gh-pages` branch. It is also available at `flanny.app/study-mandarin/`.

## Running the site locally

```bash
python3 -m http.server
```

`src/util.js` detects the host and adjusts the base URL for asset paths accordingly (flanny.app vs. localhost).

## Python scripts

Install dependencies:
```bash
pip3 install -r requirements.txt
```

Google Translate is required for filling in missing English translations. Credentials are configured via `.env`:
```
GOOGLE_APPLICATION_CREDENTIALS=/path/to/gcloud/service-account.json
```

### Refine flashcards (fills in pinyin, english, converts to traditional, deduplicates)

```bash
python3 scripts/refine.py unit <path-to-setName>
# e.g. python3 scripts/refine.py unit songs/wu_bai_norweigan_forest

python3 scripts/refine.py class <className>
# e.g. python3 scripts/refine.py class verbs
```

### Generate printable PDFs

```bash
python3 scripts/print.py unit <path-to-setName>
# e.g. python3 scripts/print.py unit songs/wu_bai_norweigan_forest

python3 scripts/print.py class <className> <classSetIndex>
# e.g. python3 scripts/print.py class verbs 2
```

PDFs are written to `print/unit/` or `print/class/<className>/`.

## Flashcard data format and types

Flashcards come in two types:

- **`unit`** — a single CSV for a standalone topic (a song, idioms, etc.)  
  Path: `data/flashcards/unit/<path>.csv`

- **`class`** — a topic split across multiple CSVs of up to 30 cards each  
  Path: `data/flashcards/class/<name>/<name>-<index>.csv`  
  `refine.py` automatically splits class CSVs into files of 30.

CSV columns: `phrase, english, pinyin, color, comments`  
You can omit `english` and `pinyin` — `refine.py` will fill them in. Colors are assigned randomly if omitted.

The `FORCE_SIMPLIFIED` list in `scripts/util/mandarin.py` contains characters that should not be converted to traditional (e.g. 了, 出, 回).

## Architecture

### Pages (`page/`)

Each page is a self-contained directory with `index.html`, `style.css`, and a JS file. They share:
- `src/base.css` — global styles
- `src/util.js` — shared utilities: CSV loading (`loadCsv`), `StorageUtil` (localStorage), color helpers, per-device app redirect logic, and `getCharacterHtml`/`renderHanziCharacter` for rendering annotated characters

The **Read** page (`page/read/`) loads `data/dictionary.csv` to annotate pasted text with pinyin and zhuyin per character.

The **Flashcard** page (`page/flashcards/`) loads individual flashcard CSVs on demand. Known cards are persisted per-set in localStorage. The set selector in `flashcard/index.html` must be updated manually when new sets are added.

The **Zhuyin Trainer** page (`page/zhuyin-trainer/`) is a standalone drill tool.

### Data pipeline (`scripts/`)

`scripts/util/mandarin.py` is the core utility — it wraps the `pinyin` library, `hanziconv` for simplified↔traditional conversion, and the Google Translate API. It loads the Hanzi-English and PinyinToneless-Zhuyin maps at import time from `data/maps/`.

`scripts/setup/` contains one-time scripts for building the maps and dictionary from external source data in `data/source/`.

`data/dictionary.csv` is the character-level lookup used by the Read page. It is generated by `scripts/setup/gen-dictionary.py`.
